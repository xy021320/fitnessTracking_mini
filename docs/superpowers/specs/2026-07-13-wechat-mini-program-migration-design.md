# 铸力微信小程序迁移设计说明

## 目标

将当前 React/Vite 健身记录原型迁移为可编译、可导入微信开发者工具并可扫码真机预览的微信小程序。现有 Web 原型保持不变，小程序作为独立工程维护。

## 已确认方案

- 使用 Taro 4 + React 构建微信小程序，优先复用现有 React 状态模型和页面交互逻辑。
- 小程序工程位于现有项目的 `miniapp/` 目录，源码与 Web 原型互不覆盖。
- 微信小程序 AppID 固定为 `wxcbad07e3fb2b6b8e`。
- 首版数据仅保存在微信客户端本地，不接入登录、后端、云开发或网络接口。
- 页面视觉继续遵循现有已确认方向：近黑与青柠首页、白底钴蓝训练页、米白与橙黑数据页、深色个人管理页。

## 技术结构

### 工程

- 框架：Taro 4、React、TypeScript、Sass。
- 编译目标：仅微信小程序 `weapp`。
- 源码目录：`miniapp/src`。
- 编译目录：`miniapp/dist`。
- 微信开发者工具导入目录：`miniapp/` 根目录，由 `project.config.json` 的 `miniprogramRoot: "dist/"` 指向编译产物。
- 尺寸基准：750 设计宽度，页面适配常见手机安全区域。

### 页面与导航

使用微信小程序原生 `tabBar` 提供四个主入口：

1. 首页：今日训练摘要、快速开始、本周进度与最近训练。
2. 训练：当前训练项目、按指标组合记录、添加项目、完成训练。
3. 数据：总览、力量、有氧统计，项目表现和趋势。
4. 我的：用户摘要、目标、单位、自定义项目、提醒与隐私入口。

训练页内部弹层使用 Taro 组件实现，不增加额外路由。底部不显示已被用户明确删除的休息计时条。

## 模块边界

- `src/store/app-store.tsx`：全局状态、微信本地存储读取与持久化。
- `src/domain/exercises.ts`：项目创建、指标校验、预设项目。
- `src/domain/analytics.ts`：总训练量、距离、时长、配速、项目统计等纯函数。
- `src/domain/sessions.ts`：将当前训练转换为历史 session 快照。
- `src/components/exercise-logger`：根据指标组合显示重量、次数、组数、时长和距离输入。
- `src/components/add-exercise-sheet`：预设项目选择、自定义项目创建与校验。
- `src/components/bottom-sheet`：小程序端通用底部弹层。
- `src/pages/*`：四个页面，仅组合组件和触发领域动作，不在页面内重复统计规则。

## 数据模型

### ExerciseDefinition

- `id: string`
- `name: string`
- `category: 'strength' | 'cardio' | 'conditioning' | 'mobility' | 'custom'`
- `metrics: Array<'weight' | 'reps' | 'sets' | 'duration' | 'distance'>`
- `custom: boolean`

项目指标可自由组合。哑铃、杠铃等力量项目使用重量、次数、组数；跳绳可以记录次数和时长；跑步记录距离和时长；其他自定义项目至少选择一个指标。

### WorkoutSession

每次完成训练保存日期、总时长和项目记录快照。力量项目保存已完成组；其他项目保存其选择指标的实际数值。历史记录不依赖后续项目库修改。

### 持久化

- 使用 `Taro.getStorageSync` 与 `Taro.setStorageSync`。
- 存储键为 `zhu-li-app-state-v1`。
- 首次启动使用现有演示数据，之后使用本地状态。
- 读取失败或数据结构无效时回退到初始状态，不阻断页面打开。
- 每次新增项目、完成组、完成训练或修改偏好后立即持久化。

## 核心交互

1. 首页点击“开始训练”切换至训练 Tab。
2. 训练页允许编辑当前项目数据，并可添加预设或自定义项目。
3. 自定义项目名称为空或未选择指标时不可保存，页面显示明确提示。
4. 数值输入只接收非负数，空值不参与统计。
5. 只有存在已完成训练内容时才允许完成训练。
6. 完成训练后生成 session 快照、持久化并切换至数据 Tab。
7. 数据页完全根据历史 session 派生，不展示与记录无关的固定假数据。

## 小程序兼容约束

- 使用 `View`、`Text`、`Button`、`Input`、`ScrollView` 等 Taro 组件，不依赖浏览器 DOM API。
- 不迁移 Recharts；趋势图首版使用小程序兼容的 View/CSS 柱线组合，避免引入体积较大的图表库。
- 图标使用小型本地组件或文字图形，不依赖当前 Web 端 Phosphor React 包。
- 所有可点击区域不小于 44px，输入框使用合适的微信键盘类型。
- 页面底部预留安全区，避免 TabBar 和全面屏 Home Indicator 遮挡操作。

## 错误处理

- 本地存储读取或写入异常不会导致白屏；读取异常回退初始数据，写入异常保留当前内存状态。
- 不合法的项目名称、空指标组合和负数输入在提交前拦截。
- 空训练不能生成 session。
- 统计函数忽略未完成组、无效数字与负值。

## 测试与验收

- 领域函数测试覆盖项目校验、训练量、距离、时长、配速、session 生成和异常数据。
- 小程序构建命令成功生成 `miniapp/dist/project.config.json`，其中 AppID 为 `wxcbad07e3fb2b6b8e`。
- 微信开发者工具可直接导入 `miniapp/` 根目录，四个 Tab 均可打开。
- 可创建“重量 + 次数 + 组数”“次数 + 时长”“距离 + 时长”等项目组合。
- 完成训练后，数据页总览、趋势和项目表现立即更新；重新打开小程序后数据仍存在。
- 在常见 iPhone 与 Android 模拟器尺寸下无横向滚动、TabBar 遮挡或不可达主操作。
- 训练页不出现“休息 / 跳过”底部计时条。

## 交付结果

- 可维护的 `miniapp/` Taro 源码工程。
- 可由微信开发者工具读取的 `miniapp/dist` 编译产物。
- 项目内运行说明，包含安装、构建、导入和手机扫码预览步骤。

## 明确不做

- 微信登录、手机号授权、云开发、远程数据库和多设备同步。
- GPS 实时轨迹、运动传感器、健康平台或穿戴设备同步。
- 支付、社交动态、排行榜、分享裂变与正式发布审核。
- 后台计时、系统通知和真实训练提醒。
